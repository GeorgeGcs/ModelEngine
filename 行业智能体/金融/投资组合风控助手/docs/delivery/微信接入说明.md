# 微信推送接入说明

课题定时流程的微信 MCP 工具与 ClawBot 配置见 [Nexent 微信风险推送](../../mcps/wechat/README.md)。验收时从定时任务触发风险事件，核对原生 MCP 调用、推送记录和手机确认。下文保留独立 Webhook 接入路径。

随附演示通过 `local-mock` 记录脱敏接收人、时间、消息、状态、去重和限频，应用显示「模拟」。目前使用合成接收人和消息，评审可按需求包的授权限制条款复验模拟闭环。

## 实际接入路径

1. 由具备授权的管理员准备企业微信测试企业、自建应用和受控测试接收人。用私有映射将项目 `recipient` 转成测试应用允许发送的成员标识，限制接收范围。由部署方提供可审计的 HTTPS relay 或经授权的微信工具服务，企业凭据由该服务保管。[企业微信发送应用消息](https://developer.work.weixin.qq.com/document/path/90236)
2. 当前应用提供 `WebhookGateway`。在启用真实通道的应用或 worker 中私有设置 `TOPIC16_WECHAT_WEBHOOK_URL`、可选 `TOPIC16_WECHAT_WEBHOOK_TOKEN` 及超时 `TOPIC16_WECHAT_TIMEOUT`。网关以 JSON `{recipient,message}` 请求 relay。由 relay 调用企业微信并归一化响应。单纯的 HTTP 200 需要可识别的业务受理字段。明确拒绝为 `failed`，受理为 `accepted`，超时或不可判定结果为 `unknown`。
3. 用一个获授权的测试接收人验证接受、拒绝、超时和去重限频。若使用 Nexent 微信 MCP，部署方需注册经授权的工具服务并在发布 Agent 或调度发送步骤中绑定，记录原生调用 ID 与关联回执。当前发布工作流包含价格、舆情、知识三工具，随附脚本的推送走应用模拟网关。
4. 要核验终端送达，需取得可与本次请求匹配的终端确认或可靠回调，并在报告中记录时间、消息摘要、脱敏接收人和状态。当前 relay 适配器仅记录受理，无终端确认接口。

真实通道配置、工具注册及终端送达测试需要平台账号、测试接收人和实际网关授权。现有证据覆盖模拟发送记录及应用网关回执语义。
