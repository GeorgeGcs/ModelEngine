# 部署与复演

实测基线为项目提交 `aeafe7e52193fefb3d5b9e0c25995b825e7de81f`、Nexent v2.8.3 ARM64、已发布 Agent `portfolio_integrated_workflow_v3_20261111` 第 1 版。页面由 Python 标准库 HTTP 服务直接提供 HTML、CSS 和原生 JavaScript，无前端构建依赖。Python 3.11 或 3.12，MCP 依赖固定于 [requirements.txt](../../integration/requirements.txt)。

## 建立隔离实例

1. 按 Nexent v2.8.3 的部署文档启动配置、北向、runtime 和独立数据服务。给文档处理服务配置专用写入端，独立 PostgreSQL、Redis、Elasticsearch、MinIO 及 Elasticsearch API Key。确认北向能访问实际 runtime 和文档处理接口，Agent 列表为空。
2. 从课题目录创建应用解释器。为平台配置 Qwen3.8-27B 模型、BGE-M3 1024 维嵌入模型、用于知识资产的独立身份与物理索引。模型认证、内部 JWT 和北向令牌从各自的私有配置注入。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r integration/requirements.txt
export TOPIC16_KB_ROLE=asset_admin
.venv/bin/python -m knowledge assets --db "$TOPIC16_KB_DB" --output "$PRIVATE_EVIDENCE/assets.json"
.venv/bin/python -m knowledge import --db "$TOPIC16_KB_DB" --output "$PRIVATE_EVIDENCE/import-1.json"
```

等待三个文档均为 `verified`。索引处理中用新输出文件再次检查已上传路径。检查源文件哈希以及资产身份允许下载、普通身份拒绝下载。详见 [知识库资产、权限和索引](../../knowledge/README.md)。

## 安装运行适配并注册三工具

1. 以容器实际解释器定位 `managed_mcp.py`、`run_agent.py`、`core_agent.py`。核对 [观察补丁清单](../../eval/nexent/deployment/observation-manifest.json) 的基线和候选哈希。使用 [平台部署适配](../../eval/nexent/deployment/README.md) 的准备器生成只读 overlay。把 [工作流协议](../../integration/dispatch.py) 按清单的哈希校验后复制到启动目录，文件名为 `topic16_dispatch_protocol.py`。
2. 为每个隔离实例生成独立的 32 字节随机签名密钥，保存在权限为 `0600` 的私有文件内。应用与对应 runtime 使用同一密钥内容，分别设置 `TOPIC16_DISPATCH_KEY_FILE` 为各自可读的路径。仅 runtime 设置 `TOPIC16_WORKFLOW_AGENT=portfolio_integrated_workflow_v3_20261111`、`TOPIC16_OBJECT_RECEIPTS=1`、`TOPIC16_RECEIPTS_DIR` 和唯一 `TOPIC16_OBSERVATION_RUN_ID`。预建应用可只读且 runtime 可追加的 `0600` 回执文件。应用设置 `NEXENT_EXECUTION_RECORDS` 指向同一文件。
3. 各工具服务使用私有监听地址和不同端口。知识 MCP 设置 `TOPIC16_KB_ROLE=risk_reader`，与应用共用 `TOPIC16_KB_DB`。设置 `TOPIC16_KB_BASE_URL`、`TOPIC16_KB_API_TOKEN`、`TOPIC16_KB_INDEX` 等私有值。以下变量须先配置成 Nexent 可访问的隔离监听地址与端口。

```bash
.venv/bin/python -m mcps.portfolio_rules.server --transport streamable-http --host "$MCP_BIND" --port "$PRICE_PORT"
.venv/bin/python -m mcps.news_risk.server --transport streamable-http --host "$MCP_BIND" --port "$NEWS_PORT"
.venv/bin/python -m mcps.knowledge.server --transport streamable-http --host "$MCP_BIND" --port "$KB_PORT"
```

4. 在 Nexent 注册三个 MCP，按 [导出包](../../agent.json) 的服务名称和各工具的输入 schema 校验绑定。复制导出包到私有区，按目标实例实际地址替换三个 `mcp_url`，使用目标租户与实际模型名称和 ID。将派生包的 `data` 作为 `agent_info` 交给原生 `POST /agent/import`。导入返回 Agent ID 后发布。保留 Agent 名称与描述标记 `topic16-workflow:portfolio_integrated_workflow_v3_20261111`。

## 启动应用和验证

在应用进程配置 `NEXENT_BASE_URL`、`NEXENT_API_PREFIX=/nb/v1`、`NEXENT_API_TOKEN`、`NEXENT_AGENT_NAME`、`NEXENT_VERSION`、`NEXENT_MODEL`、`NEXENT_EXECUTION_RECORDS`、`TOPIC16_DISPATCH_KEY_FILE`、`TOPIC16_KB_DB`、`TOPIC16_INTEGRATION_EVIDENCE_DIR`。按 [集成说明](../../integration/README.md) 使用实际发布配置构建工具库存并执行预检。

```bash
.venv/bin/python -m integration.check --mode nexent-integrated --db "$TOPIC16_KB_DB" --ports '' --inventory "$PRIVATE_EVIDENCE/inventory.json" --probe-platform --output "$PRIVATE_EVIDENCE/native-check.json"
.venv/bin/python -m app.server --host 127.0.0.1 --port 8765 --db "$TOPIC16_KB_DB" --gateway local-mock
```

在本机打开 `http://127.0.0.1:8765/`。按 [操作说明](操作说明.md) 运行三组，或调用用例脚本。使用种子 `161118` 抽取股票、基金、混合各一组，每组重复三次。验真时从 SQLite、组件文件和原生回执独立核对调用 ID、实际参数和结果。

```bash
.venv/bin/python docs/delivery/verify_cases.py --output "$PRIVATE_EVIDENCE/cases.json"
.venv/bin/python -m integration.rehearsal plan --seed 161118 --output "$PRIVATE_EVIDENCE/plan.json"
.venv/bin/python -m integration.rehearsal run --plan "$PRIVATE_EVIDENCE/plan.json" --mode nexent-integrated --db "$TOPIC16_KB_DB" --evidence-dir "$PRIVATE_EVIDENCE/replays" --output "$PRIVATE_EVIDENCE/replay-result.json"
```

源码、合成数据和脱敏证据可分发。模型配置密钥、内部地址、身份令牌、签名密钥、原始 SSE、SQLite 和完整回执均保存在验收机私有区。
