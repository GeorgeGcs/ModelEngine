# 本地可操作演示与逐条验收对照

> **风险提示仅供参考，不构成投资建议；系统输出为辅助建议，重大风险须人工核实。**
> 全部组合、标的、行情、舆情、接收人和网关回执均为虚构模拟数据。

对应课题 16 的三个组合闭环、推送去重与频率限制、以及风险类别覆盖。
本页只记录**本地产品开发**已真实跑出的结果；真实 Nexent 编排、真实微信送达、
连续 24 小时调度观测与人工盲评均另见下方「未验证项」，不得混同。

## 1. 运行命令（PowerShell，工作目录为课题目录）

```powershell
$P = '.\.venv\Scripts\python.exe'

# A. 启动可点击页面（保持在线，浏览器打开 http://127.0.0.1:8765/）
& $P -m app.server --host 127.0.0.1 --port 8765

# B. 一键跑完三组合闭环演示（经公开接口，服务保持在线可查回）
& $P -m app.demo --port 8765

# C. 只跑演示链路后退出（CI / 复核用，不占端口）
& $P -m app.demo --port 8766 --no-serve

# D. 回归测试
& $P -m unittest discover -s app/tests -p "test_*.py" -v
```

`app/demo.py` 默认在 `data/demo_run_<时间戳>.db` 新建数据库，**绝不覆盖已有数据**；
数据库与 WAL/SHM 已被 `.gitignore` 忽略。页面默认使用 `data/local_app.db`，
重启服务后组合、持仓、信号与推送回执都能重新查回。

## 2. 三组合闭环：可实际查回的记录

`python -m app.demo` 依次用 `POST /api/import` → `POST /api/monitor` →
`GET /api/records` 完成，**没有手工插库、没有预置成功状态、没有静态截图**。
输出会逐个打印股票 / 基金 / 混合组合的一条代表记录，每行含
`portfolio_id`、`risk_type`、`symbol`、`event_id`、`push_id`、`push_status`
与脱敏接收人。服务在线时可直接查回：

| 查询 | 地址 |
| --- | --- |
| 页面 | `http://127.0.0.1:8765/` |
| 某组合信号 | `http://127.0.0.1:8765/api/signals?portfolio_id=stock-demo` |
| 全部推送回执 | `http://127.0.0.1:8765/api/pushes` |
| 监控运行记录 | `http://127.0.0.1:8765/api/runs` |
| 完整汇总 | `http://127.0.0.1:8765/api/records` |

实测（一次 `--no-serve` 演示）：导入 3 个组合 / 4 项持仓，首轮监控 7 条信号与
7 条推送尝试；同一快照重复监控 7 条全部被去重，推送记录 7 → 7 未增加；
把窗口上限调为 2 后新事件被抑制 6 条；注入网关故障产生 6 条 `failed`，
恢复后重试 3 条全部 `delivered`，再次重试 3 条全部被拦截，
其余 3 条保留失败现场。库内最终 `delivered=10 / suppressed=6 / failed=3`。

## 5. 可替换 MCP 微信推送适配器

- **唯一契约**：`PushGateway.send(recipient_id, message) -> (status, failure_reason)`。
  `Service` 只依赖契约，替换实现不需要改业务编排。
- **本地模拟网关**：`LocalMockGateway`，`gateway_id="local-mock"`、
  `simulated=True`、`real_delivery=False`，回执与 `/api/health` 明确标
  `SIMULATED`，**不发起任何真实外部请求**。页面「注入模拟网关故障」可复现失败与恢复。
- **真实接入模板**：`WebhookGateway`（`gateway_id="webhook"`，`simulated=False`）。
  仅作为自建 JSON relay 接口，不声称兼容企业微信原生消息格式；从运行机器环境变量读取凭据，**不写进仓库、不进日志、不进回执**：

  ```powershell
  $env:TOPIC16_WECHAT_WEBHOOK_URL   = 'https://<自建JSON-relay地址>'
  $env:TOPIC16_WECHAT_WEBHOOK_TOKEN = '<可选 Bearer Token>'
  $env:TOPIC16_WECHAT_TIMEOUT       = '8'
  .\.venv\Scripts\python.exe -m app.server --gateway webhook
  ```

- **当前平台接入路径**：`python -m app.scheduler run` 的 `nexent-price` 模式驱动真实
  Agent，认证结果后写入本地信号并调用网关适配器。`mcp_tool_send_risk_notification`
  只是历史命名的普通 Python 函数，不能把它当作可启动 MCP server。
  本批不依赖或声称已有推送 MCP；若后续平台必须直接调推送工具，须另交实际 server。
- **回执语义**：配置URL不证明送达；业务错误 failed，业务受理 accepted，超时/响应丢失 unknown。
  所有 Webhook 回执都没有终端送达确认。详情及可运行调度命令见[第二批说明](调度与推送交付_20261110.md)。

## 6. 去重 / 限频 / 故障恢复口径

| 机制 | 实现 | 验证 |
| --- | --- | --- |
| 同一事件只发一次 | `push_records` 唯一键及事务领取/租约所有权；`event_id` 不含 run_id，同快照重复监控仍是同一事件 | `test_05`、`test_server_04`、演示第 [4] 步 |
| 不同事件限频 | 按接收人统计实际领取的 `push_attempts`（包含重试），超上限写 `status=suppressed` 并留原因；窗口与上限由 `POST /api/config` 调整 | `test_06`、`test_server_05`、演示第 [5] 步 |
| 故障恢复不重复送达 | 失败只写 `failed` 行；`retry_push` 仅原子领取 `failed/pending`，`sending/accepted/unknown` 不重发，`delivered` / `suppressed` 不重发 | `test_07`、`test_server_05`、演示第 [6] 步 |
| 回执可查 | 接收人脱敏标识、消息、创建/更新时间、送达状态、失败原因、网关标识、模拟标记、尝试次数 | `test_12` 逐字段断言 |
