# 舆情评分 v5：人工标签复用与更正声明

人工标签绑定样本、主体映射和人工判定口径；预测绑定实际执行的代码版本。
同一批文本、主体和判定口径下升级代码，不应让原人工表失效。本次取消“人工封存代码摘要
必须等于当前预测代码”的错误约束，保留旧摘要和原提交为历史信息。

版本基线为 `deec9e47a220d9499bbbb425b35eb0465a7105c4`。业务规则、人工标签、50 条分母、
43 条门槛、五份冻结件及锁均未改。报告 schema 升为 `topic16-news-risk-consistency-v5`。

## 两条证据链

| 人工证据 | 预测证据 |
| --- | --- |
| 样本与主体映射摘要、固定 profile、判定口径 | 样本与主体映射摘要、profile、判定口径 |
| 人工表实际摘要、复核者、封存与标注时间 | 当前实际代码摘要、每行代码/run/集合身份 |
| 有出处和记录时间的独立性声明或关联更正 | 非空 run ID、预测生成时间、完整输出摘要 |

人工登记的 `code_identity` 仅保存在报告的 `historical_annotation_code_identity`。
预测代码摘要仍须与当前检出实现完全相符，不能把旧预测头改成新 SHA 使用。
运行记录仍需由 A 在真实环境独立核对；JSON 字段及哈希不能单独证明实际执行或人的行为。

新预测头自动写入 `judgment_policy` 和 `payload_sha256`。后者为除该字段外的整个 JSON 对象，
以 UTF-8、键排序、无额外空格、`ensure_ascii=False`、禁止 NaN 序列化后取 SHA256。
评分报告另记录预测文件的实际字节摘要，以及评分器自身的 LF 规范化摘要。

判定口径取既有《舆情风险标注说明》第 2 至第 6 节，涵盖主体、风险、时间、证据不足与评分。
工程迁移说明不属于业务口径。该固定口径 LF 摘要为：
`38bfb5d5ed7a98394d577bcd7e6312feb4f4c8713f2c9cbe9bd894cec375f311`。
不同口径不能通过沿用 profile 名称绕过检查。

## 使用原人工登记，不改历史

新登记可记录 `judgment_policy`（由 `judgment_policy()` 获取）和带 `source`、`statement`、
`recorded_at` 的 `independence_declaration`。已有登记未记口径摘要时，使用：

- `--annotation-policy`：当时实际交给标注人的原版说明文件。
- `--annotation-manifest`：标注前准备的原材料清单，包含 `reviewer`、`preregistration_commit`、
  `prepared_at` 和 `files` 摘要表（说明文件名及 `sim_entities.json`）。

评分器核对原说明字节摘要、业务章节摘要、复核者、预登记提交、主体映射和材料准备时间。
无需给原登记补写字段或重填人工表。没有历史口径证据时报告缺项，不自动假定口径相同。

## 独立性更正入口

会话中出现过参考信息不能证明标注人接触过参考信息。若原记录基于这种推断误记，允许通过
`--review-correction` 显式选择有真实出处的更正。评分器不读取聊天，也不替人生成声明。
原封存记录、原时间、原标签与原报告保留。

更正 JSON 契约（以下是字段说明，不是已签署声明）：

| 字段 | 校验 |
| --- | --- |
| schema | `topic16-review-evidence-correction-v1` |
| original_registration_sha256 | 原封存记录文件实际字节 SHA256 |
| human_labels_sha256 | 当前人工表实际字节 SHA256，同时仍核对原登记 |
| annotator / sample_set_id / profile | 与原登记一致 |
| independent_review | 必须是布尔 `true` |
| source / statement | 有实际来源和明确声明内容，不能为空 |
| recorded_at | 带时区，原封存之后、当前评分之前的实际记录时间 |

更正可以晚于旧预测。它只纠正独立性证据，不改变封存时间、标签、样本或预测。
显式指定了无效更正时拒绝采用，不静默退回原声明。报告
`provenance.independence_evidence` 留下采用的声明、来源、记录时间、文件摘要、原登记摘要和原布尔值。

## 运行与迁移

在实际被测候选的课题目录、原有 Python 环境执行。没有新增依赖、网络请求或数据库迁移。
以下变量指向操作者已有私有材料以及新的结果路径，不填造时间或声明：

```bash
python -m news_risk data/news_risk/samples_50.json --profile v2 \
  --entities data/news_risk/sim_entities.json --sample-set-id NR-2026-11-09 \
  --run-id "$NEWS_RUN_ID" --output "$NEW_SYSTEM_OUTPUT"
python eval/news_risk/score.py --samples data/news_risk/samples_50.json \
  --human "$ORIGINAL_HUMAN_LABELS" --system "$NEW_SYSTEM_OUTPUT" --report "$NEW_REPORT" \
  --label-source human-annotation --profile v2 --registration "$ORIGINAL_SEALED_REGISTRATION" \
  --sample-registry data/news_risk/sample_registry.json \
  --annotation-policy "$ARCHIVED_ANNOTATION_INSTRUCTIONS" \
  --annotation-manifest "$ORIGINAL_PACKAGE_MANIFEST" \
  --review-correction "$RECORDED_REVIEW_CORRECTION"
```

原声明完整且无更正时省略最后一个参数；新登记已绑定口径时不必提供原材料清单参数。
旧预测缺新增摘要，或不对应当前源码时，应在新 run 重新生成预测，不能手工补头。
旧评分结果保留，修复后的有效性由 A 用新报告独立复验。

`formal` 表示证据检查有效，`meets_85_percent` 表示数值至少 43/50，`pass` 须同时满足。
42/50 的有效评测仍为 formal=true、pass=false。缺真实标签保持 pending；合成夹具恒为
formal=false/pass=false；开发集禁用、字段校验和失败后旧报告失效门禁继续生效。

## 验证范围

新增 30 项合成回归，含实际在两个临时源码版本执行预测、复用同一人工表和登记；两次预测
代码身份不同，各自通过绑定校验。错代码、输出变更、错样本/主体/口径、变更标签、缺声明、
错关联更正、无时区/未来/倒序时间均拒绝。CLI 新参数及失败后旧报告失效也已执行验证。
合成夹具用于测试机制，不是人工标签或验收成绩；没有把真实人工表写入测试。

本批不改变已有 43/50 的数学结论，也不把开发回归当作正式复评或真实平台结果。
