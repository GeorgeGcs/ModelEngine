  提供有效时间仅记provided_not_window_verified；正式人工评测的固定观测窗口仍由原标注纪律约束。
- 处罚同义表述、否定/撤销、同名或近似法人、传闻/假设、历史结案/新进展、部分否认/恢复正常
  与相互矛盾均有回归。按子句和主体归属判断，未把样本ID或公司名称写进规则。

  engineering_would_pass仅用于显式工程夹具，不是正式验收结果。
- 旧门禁缺代码绑定、完整时序、固定候选profile核对；新版非夹具要求登记v2和输出代码身份一致，
  逐行run/集合/代码摘要与输出头一致。默认来源也执行结构及原文证据检查。
  人工文件存在但坏且预测缺失时先报告结构失败，不再报pending。

## 正式评分迁移（不生成真人标注）

报告schema为topic16-news-risk-consistency-v4；正式登记新增v2模板。
旧v1登记保持原样，缺新证据时只作未核实材料，不能事后补造登记时间或签署人。
候选仍NR-2026-11-09/profile=v2，分母50、阈值43；开发集按实际内容指纹禁用。

1. 选定本次完整代码SHA，在标注前封存代码摘要及登记提交；代码指纹对规定源文件进行LF归一化。
   可运行 `python -c "import json; from eval.news_risk.provenance import code_identity; print(json.dumps(code_identity(),indent=2))"`。
   将实际结果放入私有登记的code_identity；登记模板不是已签署记录。
2. 真实独立复核者仅查看原文，在私有文件中标注；真实封存后记录human_labels_sha256。
   时序必须registered_at≤annotation_started_at≤sealed_at≤generated_at≤评分时刻，均含显式时区。
   preregistered_commit须完整SHA。字段声明只供机器一致性检查，A/审计人还须验证真实Git记录、
   标注身份和独立性；哈希或JSON声明本身不能证明真人评审。
3. 人工封存后生成预测，显式指定集合ID和新run：

```bash
python -m news_risk data/news_risk/samples_50.json --profile v2 \
  --entities data/news_risk/sim_entities.json --sample-set-id NR-2026-11-09 \
  --run-id "$NEWS_RUN_ID" --output "$SYSTEM_OUTPUT"
python eval/news_risk/score.py --samples data/news_risk/samples_50.json \
  --human "$HUMAN_LABELS" --system "$SYSTEM_OUTPUT" --report "$NEW_REPORT" \
  --label-source human-annotation --profile v2 --registration "$REGISTRATION" \
  --sample-registry data/news_risk/sample_registry.json
```

缺真人文件仍pending/exit2，本批没有生成实际候选答案或真人标签。
formal只代表证据链通过机器检查；meets_85_percent只代表≥43；pass必须两者都成立。
有效真实42/50仍formal=true、meets=false、pass=false、formal-not-met，数学边界以隔离单元测试验证。
结构错误拒绝；旧报告保留为stale_report并标失效，重复失效不嵌套，后续合法运行可以产生新报告。
开发评分器已检查：坏预测不打开参考文件，旧报告失效；未改已正确的开发评分逻辑。

## MCP与运行时观察

精确工具名保持assess_news_risk、assess_news_risk_v2；SDK 2.3.0。
实际SDK导出的完整schema在mcps/news_risk/schema.json；v2请求为news和entities，
news含必填symbol/text，可选sample_id/published_at/source。成功是判定对象（无风险也不是[]），
显式isError=false，文本JSON与structuredContent.result相等；价格仍是数组契约。

```bash
python -m mcps.news_risk.server --transport streamable-http --host 127.0.0.1 --port 8770
python -m unittest discover -s mcps/news_risk/tests -v
```

绑定端口按A隔离实例配置，默认不对外开放。非法输入在真实SDK处理器中为isError=true；
外层可以正常接受错误封套。取消不转换为成功，超时在调用边界用mock覆盖；同步规则没有虚构超时机制。

Nexent v2.8.3现有SDK patch未改。新增可选启动适配topic16_object_observation.py，
只接受哈希为d64ffb9157d6407398cd481d7af09ddd56abf0b2adef34ebbabf66706fed3d96的patched managed_mcp。
新独立runtime设置TOPIC16_OBJECT_RECEIPTS=1以及独立TOPIC16_RECEIPTS_DIR/TOPIC16_OBSERVATION_RUN_ID，
才开启舆情对象捕获；默认仍只捕获价格。新startup组件hash由observation-manifest.json锁定，
使用原prepare_observation_overlay.py生成隔离overlay。旧dbdf965观测窗口不启用或升级此组件。
回退使用前一个独立部署包或关闭新runtime的该开关，不改旧窗口。

该适配保留实际call_id、news/entities、显式成功/错误、外层接受、文本与结构化对象，不发起调用。
缺ID、缺显式成功、双通道不等、错误/超时/取消均不能成功。观察流ID不是业务run_id。
A仍须以可信目标调用事件关联唯一同次原生回执，核对实际参数；正文键、仅调用、冲突/异run回执不能认证。
新增适配本地捕获测试不能证明生产调度ID传播，真实Linux严格回归和原生链路须A独立实测。
